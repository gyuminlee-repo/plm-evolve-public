# GAP-2 real-DMS validation: measured numbers (factual)

Generated by `scripts/validate_gap2_dms.py` (active-learning recall) and
`scripts/spearman_pooling_probe.py` (paired held-out Spearman discriminator) on
real EVOLVEpro DMS oracle data. This note records the raw numbers and the pilot
bottom line.

## Question
In the EVOLVEpro few-shot loop, does greedy / a top-layer on `mutated_token`
embeddings rank or reach top variants better than `mean`, on the SAME variants /
same real ESM-2 / same loop / same oracle? Mean-vs-mutated_token is the ONLY
difference.

## BOTTOM LINE (pilot, 2 CPU proteins, 35M + 150M)
`mutated_token` shows NO advantage over `mean` on the application-relevant metric
(recall@k / max_found) ANYWHERE that metric is meaningful. On cas12f (the only
protein where greedy beats random, so recall is informative) there is no pooling
separation on EITHER recall OR Spearman, at 35M OR 150M. The single `mutated_token`
win is kelsic@150M on the Spearman proxy ONLY, and on kelsic the recall metric is
broken for BOTH poolings (a rare-beneficial needle the loop cannot pin). So GAP-2
is NOT a robust general win in this pilot. A real verdict needs a GPU multi-protein
campaign (more proteins, larger models, full mutant sets).

## Discriminator: paired held-out Spearman(pred, true), RF top-layer
Per (train_size, seed): one random split on the shared variant order, fit the core
TopLayerRegressor (RF, random_state=1, identical for both poolings) on train,
Spearman on the held-out remainder. Verdict from the PAIRED gap
diff = Spearman(mutated) - Spearman(mean); "separated" iff |mean gap| > 2*SE_diff
(cancels the shared split-noise that swamped recall@10). 20 seeds.

Criterion: the table above is regenerated under the current default
`criterion="friedman_mse"` (matching original EVOLVEpro; prior rows used the
sklearn default `squared_error`). For the single-hash caches (cas12f 35M,
kelsic 35M) the shift is criterion-only (~0.003), verdicts unchanged. kelsic
150M is now computed on the figure-consistent variant subset (the prior rows
used a different subsample); its larger shift moves ts=32 from no-separation to
MUTATED-wins, so kelsic 150M now favours mutated_token at all three train sizes.
cas12f 150M mutated_token was re-embedded (the cache was absent) to complete the
table. The finding stands: mutated_token has NO consistent advantage over mean.
It is model-dependent (mean wins on kelsic 35M, mutated wins on kelsic 150M, no
separation on cas12f), and on ESM-C mean separates or ties with mutated_token
never winning (esmc_300m gap -0.11/-0.09/+0.01, esmc_600m -0.09/-0.06/+0.01 at
ts=16/32/64). So mutated_token is not a reliable pooling upgrade.

## Active-learning recall@10 (the application metric; underpowered for pooling)
Loop: n_init=10, n_per_round=8, n_rounds=6 (budget 58), 10 seeds.
recall@k = |measured_final INTERSECT oracle_true_top_k| / k.

| dataset/model | greedy_mean | greedy_mutated | random | additive |
|---|---|---|---|---|
| kelsic 35M | 0.120 +/- 0.132 | 0.050 +/- 0.108 | 0.060 | 0.510 (artifact) |
| kelsic 150M | 0.030 +/- 0.067 | 0.040 +/- 0.084 | 0.060 | 0.510 (artifact) |
| cas12f 35M | 0.200 +/- 0.115 | 0.160 +/- 0.158 | 0.140 | 0.330 (artifact) |
| cas12f 150M | 0.250 +/- 0.127 | 0.180 +/- 0.148 | 0.140 | 0.330 (artifact) |

mean-vs-mutated recall diffs all sit BELOW the seed-noise floor (SE ~ 0.03-0.05),
so recall cannot resolve the pooling effect (hence the Spearman discriminator).

## Diagnoses that were load-bearing
1. The additive one-hot baseline is DEGENERATE on a single-mutant-only landscape:
   each single mutant is its own one-hot column, so an unmeasured candidate has an
   all-zero feature row and ridge predicts the intercept for EVERY unseen variant
   (confirmed: prediction std = 0.000, distinct = 1, all == intercept). Its recall
   is a deterministic tie-break artifact, not generalization, and is seed-independent
   (kelsic recall@10 = 0.5 for 9/10 seeds). NOT a valid additive null here.
2. kelsic greedy recall sits at random at BOTH 35M and 150M, yet kelsic embeddings
   are strongly activity-predictive (held-out Spearman 0.32-0.47). The greedy-at-
   random outcome is a SELECTION-LOOP / metric effect on a thin beneficial needle
   (global monotonicity is not ranking the rare top-10), not an embedding-signal
   failure. Larger model does not rescue recall on the needle.

## Caveats (bounding the claim)
- 2-protein CPU pilot. cas12f is subsampled (350/7941) while kelsic is full (1368),
  so length, mutant density and n co-vary across the two proteins; this pilot does
  NOT isolate a length (1/L) effect. No length claim is made.
- recall@k at stringent k on a thin needle is high-variance; Spearman is a lower-
  variance proxy but is not the directed-evolution objective.
- The lone kelsic@150M Spearman win is a single (protein, scale) point on a proxy
  metric; it is a curiosity to confirm or drop with a GPU campaign, not a result.

## Status
GAP-2 (mutated_token pooling) is NOT a robust general win in this pilot. The
synthetic ablation proved the MECHANISM (pooling dilution, locality-dependent); the
real-data pilot finds no advantage on the application metric where it is meaningful.
The harness (validate_gap2_dms.py + spearman_pooling_probe.py) is the durable, reusable
deliverable. Whether to chase the kelsic@150M signal with a GPU multi-protein /
larger-model campaign, or park GAP-2 and move on, is left open.
